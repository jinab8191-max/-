# 편집팀

목표는 "깔끔한 영상"이 아니라 **처음 1초에 멈추고 끝까지 보게 되는 영상**이다. 모든 결정은 "여기서 시청자가 넘길까?"를 기준으로 한다.

## 규칙
- 캡컷 초안은 ~/.pycapcut 의 pycapcut 으로 만든다(`~/.pycapcut/bin/python`). 초안 폴더: ~/Movies/CapCut/User Data/Projects/com.lveditor.draft
- 시작 전에 "캡컷에서 이 프로젝트를 닫아주세요"라고 말한다.
- 스타일 가이드 ~/릴스스타일/style-guide.md 가 있으면 **먼저 읽고 모든 숫자를 거기서 가져온다.** 없으면 아래 기본값을 쓰고, 끝날 때 "레퍼런스 분석(reels-benchmark)을 하면 더 좋아진다"고 알려준다.
- 사용자 확인은 두 번만: ① 편집 기획안 ② 자료 화면 목록. 나머지는 멈추지 않고 끝까지 간다.
- pycapcut 으로 안 되는 기능이 있으면 건너뛰지 말고 가능한 대안으로 처리하고, 무엇을 대신했는지 마지막에 알려준다.
- 형식: 파일이 세로면 숏폼(1080x1920), 가로이거나 "롱폼"이라고 하면 롱폼(1920x1080). 초안 이름은 숏폼 "릴스_러프컷", 롱폼 "롱폼_러프컷" (이미 있으면 뒤에 _2, _3).

## 기본값 (스타일 가이드가 없을 때)
| 항목 | 숏폼 | 롱폼 |
|---|---|---|
| 훅 | 첫 1초 안에 가장 강한 문장 + 화면 글자 훅 | 첫 15초 안에 "이 영상에서 얻을 것" 예고 |
| 화면 변화 없이 최대 | 3초 | 8초 |
| 침묵 | 0.3초 넘으면 자름 | 0.5초 넘으면 자름 |
| 줌 | 컷마다 100% ↔ 112% 번갈아(점프컷 줌) | 강조 문장에서만 115% |
| 자막 | 한 줄 10~12자, 핵심 단어 노란색+크게 | 한 줄 18~20자, 핵심 단어만 색 |
| 효과음 | 30초에 6~10개 | 1분에 2~4개 |
| 배경음악 | 말보다 -20dB 정도 | -25dB 정도 |

## 0. 입력 정리
- 파일 1개 → 그대로.
- 폴더에 여러 개 → 파일 이름 순서로 이어 붙인다.
- 같은 장면을 동시에 찍은 2개(이름에 A캠/B캠, 또는 사용자가 다중카메라라고 함) → 9번 "다중카메라" 규칙을 먼저 적용.

## 1. 받아쓰기·분석
- whisper-cli(모델 ~/.cache/whisper/ggml-large-v3-turbo-q5_0.bin, 한국어, 단어 단위 타임스탬프)로 받아쓴다.
- 문장마다 역할을 붙인다: 훅 후보 / 문제 제기 / 본론 / 숫자·결과 / 반전 / 결론 / 행동 유도. 그리고 "재미·궁금증 점수(1~5)"를 매긴다.

## 2. 편집 기획안 (사용자 OK 받기)
아래를 표로 보여주고 OK 받으면 진행한다.
- **훅 선택**: 첫 화면에 둘 문장(점수 가장 높은 문장, 결과·반전·숫자 우선). 원래 순서가 아니면 "앞으로 끌어옴"이라고 표시. 화면 글자 훅 문구 1개(10자 안팎, 궁금증 유발).
- **뺄 구간**: NG(같은 말 반복은 마지막 것만), 군말("음·어·그·다시"), 끊긴 말, 침묵, 그리고 **재미 점수 1~2점이면서 흐름에 꼭 필요 없는 문장**.
- **구성**: 훅 → 본론 → 반전/결론 → 행동 유도, 구간별 예상 길이와 최종 길이.
- **엔딩**: 마지막 문장이 첫 문장과 이어지도록(루프) 할 수 있으면 제안.

## 3. 컷편집
- 기획안대로 자르고 이어 붙인다. 컷 사이 소리가 툭 끊기지 않게 앞뒤 0.03초 여유.
- 훅을 앞으로 끌어왔으면 훅 → 짧은 전환 → 원래 시작 순서로.

## 4. 시각 변화 (패턴 인터럽트)
- "화면 변화 없이 최대 N초" 규칙을 지킨다. 넘는 구간은 다음 중 하나로 채운다: 줌인/줌아웃, 화면 위치 살짝 이동, 자료 화면(B롤), 화면 글자/이모지 강조, 카메라 전환(다중카메라일 때).
- 같은 기법을 3번 연속 쓰지 않는다.
- 강조 문장(숫자·반전·결론)은 더 크게 줌(115~125%)하거나 0.1초 짧은 흔들림/플래시 느낌을 준다.

## 5. 자막
- 문맥으로 오타 수정(예: 컵 편집 → 컷편집, 리스 → 릴스).
- 핵심 단어(숫자, 결과, 감정 단어, 반전 단어)는 강조 색·크게. 한 자막에 강조는 1개.
- 훅 구간에는 화면 글자 훅을 큰 글씨로 1~2초 따로 띄운다.
- 스타일 가이드의 위치·폰트 느낌·테두리를 따른다.

## 6. 효과음·전환·음악
- 효과음: 첫 문장 whoosh / 숫자·반전 pop 또는 ding / 목록 시작 click / 주제 전환 swoosh / 행동 유도 ding. 소리 시작은 해당 순간 0.05초 전. ~/릴스효과음 에 맞는 파일이 있으면 먼저 쓰고, 없으면 https://api.openverse.org/v1/audio/?q=검색어&license=cc0,by 에서 4초 이하 첫 결과. "효과음" 트랙, 볼륨 50%.
- 장면 전환: 이야기가 바뀌는 지점에만 0.3초 안팎(pycapcut TransitionType). 같은 전환 반복 금지. 훅 바로 뒤는 빠른 줌/휙 넘김.
- 배경음악: ~/릴스음악 에 파일이 있으면 분위기에 맞는 것 하나를 "음악" 트랙에 깐다. 말할 때는 낮게, 말 없는 순간은 살짝 올린다. 없으면 건너뛰고 알려준다.
- CC BY 소리를 썼으면 캡션용 출처 문구를 만든다.

## 6-1. 모션그래픽
- 생성기: `~/.pycapcut/bin/python ~/릴스스타일/mg.py` (투명 배경 .mov 를 만든다. 색·폰트는 ~/릴스스타일/brand.json). 없으면 https://raw.githubusercontent.com/jinab8191-max/-/claude/reels-editing-tools-setup-q0g0og/motion/mg.py 를 그 경로에 받고 `~/.pycapcut/bin/pip install pillow`.
- 스타일 가이드의 "모션그래픽" 섹션이 있으면 그 빈도·종류를 따른다. 없으면 기본:
  | 순간 | 템플릿 | 숏폼 | 롱폼 |
  |---|---|---|---|
  | 첫 화면 훅 | `hook` (글자 훅 + `--sub` 한 줄) | 0~1.5초 | 0~3초 |
  | 숫자·금액·퍼센트 말할 때 | `counter` (`--suffix` 단위) | 있을 때마다 | 있을 때마다 |
  | 핵심 단어·반전 | `keyword` | 30초에 2~3개 | 1분에 1개 |
  | 화면 속 특정 부분 가리킬 때 | `highlight` (`--x --y` 위치) | 자료 화면 위 | 자료 화면 위 |
  | 주제 바뀔 때 | `chapter` (`--num`) | 안 씀 | 챕터마다 |
  | 마지막 행동 유도 | `cta` | 마지막 3초 | 마지막 5초 |
  | 영상 전체 | `progress` (`--duration` 전체 길이) | 스타일 가이드에 있을 때만 | 안 씀 |
- 영상 하나에 필요한 것을 spec.json 하나로 만들어 `mg.py batch spec.json` 으로 한 번에 렌더한다. 저장 위치 ~/릴스자료/모션/<초안 이름>/.
- 렌더된 .mov 를 "모션그래픽" 트랙(맨 위)에 해당 시간에 올린다. 자막과 겹치면 모션그래픽 위치(`--y`)를 옮긴다.
- 캡컷에서 투명 부분이 검게 보이면 `--green` 으로 다시 만들고 사용자에게 캡컷 "크로마키"로 초록을 빼라고 알려준다.
- 모션그래픽과 줌을 같은 순간에 겹치지 않는다(둘 다 시각 변화라 하나면 충분).

## 7. 자료 화면 (B롤)
- 사이트·앱·숫자·결과물을 말하는 문장을 고르고(숏폼 30초당 3~5곳, 롱폼 1분당 1~2곳) 보여줄 화면 목록을 먼저 보여주고 OK 받는다. 사용자가 이번엔 빼라고 하면 건너뛴다.
- 크롬으로 페이지를 열고 screencapture -v 로 3~5초씩 녹화하며 천천히 스크롤. ~/릴스자료 에 저장.
- 숏폼은 화면 위쪽 절반, 롱폼은 전체 화면 또는 화면 속 화면으로 "자료 화면" 트랙에 올린다.
- 로그인·결제·개인정보가 보이는 화면은 찍지 않는다.

## 8. 자체 점검 (저장 전에 반드시)
다음을 하나씩 확인하고 못 지킨 건 고친 뒤 저장한다.
- [ ] 첫 1초(롱폼은 첫 15초)에 훅이 있다
- [ ] 화면 변화 없는 구간이 기준을 넘지 않는다
- [ ] 0.3초 넘는 침묵이 없다(숏폼)
- [ ] 자막 오타·잘린 문장이 없다
- [ ] 효과음·전환이 같은 것만 반복되지 않는다
- [ ] 끝이 질문·행동 유도 또는 루프로 끝난다

## 9. 다중카메라 (카메라 2대 동시 촬영)
- 두 영상의 소리를 비교(교차상관)해서 싱크 오프셋을 구한다. 싱크가 0.05초 넘게 어긋나 보이면 사용자에게 알린다.
- 소리는 음질 좋은 쪽(기본 A캠) 하나만 쓰고 다른 쪽은 음소거.
- 컷편집은 A캠 기준으로 하고 B캠에도 같은 구간을 똑같이 적용한다.
- 카메라 선택: 문장 경계에서 바꾼다. 같은 카메라가 숏폼 5초·롱폼 15초를 넘지 않게. 강조 문장은 클로즈업 쪽, 설명·목록은 넓은 쪽. 두 사람 대화면 말하는 사람 쪽 카메라.
- 카메라를 바꾼 컷에서는 줌 효과를 겹쳐 쓰지 않는다(전환 자체가 시각 변화).

## 10. 롱폼 추가 작업
- 챕터 구간을 나누고 유튜브 설명란용 타임스탬프(00:00 제목)를 만든다.
- 숏폼으로 잘라 쓰기 좋은 구간 3곳(30~60초, 훅이 강한 곳)을 시간과 함께 추천한다.

## 11. 마무리
- 초안 저장 후 "캡컷을 다시 열어주세요"라고 알려준다.
- 요약 표: 최종 길이, 뺀 구간 수, 훅 문장, 자막 줄 수, 줌·효과음·전환·자료 화면·카메라 전환 개수, 자체 점검 결과, 대신 처리한 것.
- 사용자가 캡컷에서 고친 점을 말해주면 그 내용을 이 파일 맨 아래 "내 취향" 에 한 줄로 추가한다.
